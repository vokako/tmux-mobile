# Task Board — one board per project, kept by humans and agents alike

The `issues`/`issue_notes` board: fixed columns, per-project numbering, dispatch-by-assignment, the review handoff, and how it joins the agents' derived status without merging with it. Requirements for the page are in `../../requirements/pages/hub.md` (Board section) and the CLI verbs in `tmm-cli.md`.

## Rules and their reasons

### A card shows WHO is on it, lit while that agent runs (board #293, 2026-10-01)

Owner, 14:38, after the promo: "board 里不同的 agent 分别在处理哪个，视频里那个可视化比我们当前的看起来更好一些". The card's `· @assignee` accent text is now the assignee's `.ava` tile (the app-wide 16px avatar atom, lettered) filled with the agent's own ink, then the name in `--text2`. The ink is `agentHue(name)`, the same colour the feed header, sysline, roster and @mentions use (#292). While that agent's hub_agents row is running (`stateIsLive`, the roster's and drawer's definition), a 6px dot wearing `.live-dot` sits on the tile's top-right corner; idle, stopped or removed means no dot (at rest is achromatic). Nothing on the board lights it: activity on an issue is not work (tenet 8). The rows are the ones Board already polls every 8s for the assignee picker, so there is no second hub_agents loop. `board.ts` `assigneeView` decides all of this as a pure function. The human assignee keeps plain `@human` text and no tile, because the human is not an agent; unassigned is unchanged. The detail's assignee Select shows the same tile per option (`Option.ink`, rendered as `.ava` in Select's existing icon column). The hover card (#284) is unchanged. Pinned by `board.test.ts` (assigneeView), `Board.source.test.ts` (tile, ink, live dot, one hubAgents call) and `Board.mount.test.ts` (lit while working, cleared by the next poll once idle). Not in scope, for the owner to ask separately: a SHIP stamp, a per-agent "doing" line, the roster on the board page.

### A card's body preview is prose, in the content face (board #246, 2026-09-27)

A card is a `<button>`, and `app.css` gives every button the display face (`--font-display`, the chrome role). The title keeps it, because an issue title is the card's name. The body preview `.c-body` is the issue's own text, so it names the content role, `font-family: var(--font-ui)`, like every other prose surface (design-language.md, three font roles). This closes the #154 audit's A3 leftover. Pinned by `Board.source.test.ts` "the card body preview is prose…", which fails when the declaration is removed.

### Note-copy outcomes use the shared model and clipboard (#167 batch 2, 2026-09-12)

After the mechanical move, the same message-action model also accepts Feed
keys and records a failed attempt. Board calls `core/clipboard`, including its
insecure-context fallback, instead of writing through a private navigator API.
The raw note body is unchanged. A successful copy owns its 1500ms completion
expiry; failure is a persistent, retryable local error. Context transitions
cancel the scheduled expiry and invalidate an older clipboard completion.

The error uses the shared OperationFeedback and the local positioning action,
anchored to the live Copy button inside the notes scrollport. It cannot sit
over the note input or the triggering action as the fixed-corner prototype did.
Scroll/resize tracking is local and disposed; the existing outside/Escape
owner includes the error's Close control. No row, footer, global listener,
new clipboard writer or reading-layout change is introduced.

Each entry is a decision with the reason it was made; treat them as normative. They lived in the root `CLAUDE.md` until 2026-09-02 (board #73), when that file became an index and the rules moved next to the design they belong to.

### Delete failure remains in its confirmation (#167, 2026-09-12)

The old executor cleared `pendingDelete` after both success and failure;
Back could also dismiss it during the write. A failed mutation now remains
on its captured session/issue with an alert inside the same ConfirmDialog.
Pending Back is consumed without dismissing it or peeling the detail view,
and duplicate activation remains blocked by the synchronous busy guard.
Room generation and intent identity gate late completions. Only successful
deletion closes the matching detail; refresh errors use the existing board
read-error path and polling, never another destructive retry. Discard remains
neutral and explicitly offers Keep editing/Discard.

Real Board mount tests reproduce the old pending-Back failure and Cancel
wording, then verify retry, duplicate protection and successful-delete/
failed-refresh separation. The latter was already correct and is retained
as a regression guard, not claimed as a new repair.
Once mutation and refresh are separate phases, a second deletion can finish
before the first refresh returns. Review reproduced that old reply restoring
the second deleted card. `load()` now gates publication by its request ID as
well as the room, and successful deletion immediately removes its known row
and updates counts before refreshing. The ordered-promise regression returns
the newer empty list before the older populated list and requires it to stay
empty; no mutation is replayed and no refresh queue is added.

### The project has ONE task board, and both species keep it

schema v12 `issues`/`issue_notes`, session-scoped like the chat room; schema v16 makes every PUBLIC `#N` a per-project durable sequence starting at 1 (deletes leave gaps and never reuse), while the database-wide `issues.id` is hidden and retained only as the issue_notes FK; every single-row read/write resolves `session + project_number`, so different projects can both have `#1` safely; project rename moves Board rows + sequence in the same transaction, archive retains them, and permanent project delete removes issues + notes + sequence before releasing the session name (board #41); four FIXED columns (`projects::BOARD_STATUSES` = todo/doing/review/done — free text would fork the vocabulary per agent). The human writes issues on the BOARD PAGE (`hub/Board.svelte` — its own tab between Files and Agents, desktop-server-gated like Hub; owner 2026-08-29: "board单独作为一个独立的功能的页面，不用都塞到hub里"; it carries the shared project SIDEBAR (every project has its own board; a pick overrides the followed last-touched session until that moves again; compact drills list⇄board; its four fixed count chips wear the Board-only `.side-wins.grid` plus a hidden natural-width mirror so `chipCols` chooses only 4×1/2×2/1×4 from available width, localized labels and the widest count — never a 3+1 orphan, same-column dots align, and two columns are the pre-measure fallback — while Chat's variable agent chips keep the bare flex layout), polls while visible, back gesture peels detail→list then lifts the project drawer as the compact floor — never falls to the terminal; a chat-jump entry returns to the conversation instead (board #47) — and the Hub header's layout icon jumps there); agents read and update THE SAME rows via `tmm board list|show|add|take|move|note|delete` (`hub_board_*` RPCs; `take` = assignee+doing in one move; identity = TMM_AGENT else "human"). Updates PATCH field-by-field (COALESCE) so an agent's `move` cannot erase a body the human edited meanwhile; notes are the issue's own thread and bump `updated_at`; every write is session-gated in SQL so a guessed id cannot cross boards. Cards name the REPORTER (`created_by`), and UI assignment is a DISPATCH: picking a managed agent saves the field AND posts an @message (hub_post delivery types it into the pane with take/note/move instructions); that assignment brief reads as a handoff — the assigner SUBJECT leads, then the ENTIRE original title/body (never a preview excerpt: this is the agent's task input, and the bracketed-paste delivery path has no 400-character transport ceiling), then `assignNotes()`'s chronological authored note thread under its own 1200-character budget (any cut pointing to `tmm board show <id>`), and the take/note/move instructions ride LAST (board #42, #51, #79) — "Assign 给某个 Agent 去做" means the agent starts with the complete original issue plus bounded discussion context, not that a label changed (owner, 2026-08-29). `build_prompt` teaches it in one bullet and the tmm-cli skill carries the conventions (take before you start, note decisions ON the issue, only the acceptor moves to done).

**The original issue text becomes history after dispatch/work** (board #43): schema v15 persists `agent_touched`; `editable` requires no current assignee AND no Agent save/note ever, and the store rejects title/body patches after either gate closes (clearing assignment or moving back never erases Agent activity). Status/assignee/new notes remain writable; locked title/body and every note are selectable static text.

**The status slider's chosen stop is a SELECTED segment, not a CTA** (review, 2026-09-03): `.seg-b.on` wore the solid `--accent-fill`/`--accent-fill-ink` — the dialect design-language.md reserves for a solid call to action (the send button) — while every other segmented control (Preferences' `.segmented button.active`) says selected as accent outline + `--accent-bg` wash + accent ink. The slider now says the same, the outline as an inset ring because its stops share one bordered track; `Board.source.test.ts` pins wash + line and bans the fill.

**The slider's thumb is NESTED in the track** (board #95: "边缘线条都出框了…要像是真的一个滑块在四个状态滑动"): the pill used to slide FLUSH against the track's own border — full `--ui-radius-control` plus a 1px ring grinding on the 1px frame, and full-height stop dividers running into it — which read as lines escaping the box. Now the track carries 3px padding, the thumb and the stops wear the inner radius (`calc(--ui-radius-control - 3px)`, the nesting rule; the `.slide-pill` override is scoped to `.seg` so the rail/tab pills keep the atom's own), and the dividers are short centre DETENTS (25%–75% height pseudos) that never touch the frame and go transparent around the thumb. `Board.source.test.ts` pins the padding, the nested radii, the detents and their yield.

**The four areas use the whole width; only the detail is capped** (board #96: "四个区域…要更有效利用屏幕资源，左右占满"): `.board` wore `max-width: 1100px; margin: 0 auto`, which centred the columns and wasted a wide screen's margins. The cap is gone from the container — the column-count ladder still answers the board CONTAINER (board #27), so nothing about 1/2/4 changes — and moved to the issue DETAIL view, where prose and form fields genuinely read better bounded. `Board.source.test.ts` pins both.

**A Board note wears Chat's Copy-action dialect, not a second one** (board #46; the row began in Chat, was briefly retired there — board #48 — and is back as Chat's tap-revealed Copy/Raw row since 2026-09-07): tapping its fit-content bubble reveals the shared global `.m-acts` absolute overlay with one Copy button; the raw `n.body` reaches the clipboard, text selection wins over tap, the timestamp is the accessible trigger, and outside/Escape/context switch/Copied close it without layout change. Its `{open,copied,gen}` state captures identity both for the clipboard attempt BEFORE `await` and for the dismiss timer AFTER it, so neither a deferred resolve nor a stale timeout can stamp/close a later note or issue.

Ownership (#167, 2026-09-12): the existing generation model and its unit test
now live in `hub/message-actions.ts` and `hub/message-actions.test.ts`, so Feed
can adopt the same model next. This move only renames the exports; Board keeps
its numeric row index, `-1` sentinel, clipboard path and component lifetime.

**A Board detail's ✓ answers the edit** (board #48): only the full successful save/assignment path returns to the refreshed list; a failure keeps the detail, error and typed draft for retry. The trailing action order is delete → cancel → ✓, so ✓ is rightmost whenever present and cancel buffers it from the destructive verb.

**A move to DONE wakes nobody, and a titleless issue is named by its body** (moved here from tmm-cli.md, board #102). Board #30 (owner, 2026-08-31: "如果任务我标记为done可以不用给agent发送提示了"): a save that MOVES the issue to done suppresses the WHOLE assignee notice — even when title/body ride along with the acceptance, closing the work leaves the executor nothing to act on; the room's `[tmm] board … → done` line still records it, and a LATER edit to an already-done issue (a reopen included) is ordinary news again (`board_change_notice`, pure + tested). Board #31: the title is OPTIONAL — `issue_save` refuses only a CONTENTLESS issue (a patch may clear the title while a body remains, and the cleared title persists empty verbatim); every surface that NAMES an issue speaks ONE fallback, `projects::issue_ref` (client mirror `issueRef`): trimmed title, else the body whitespace-squashed and cut at `ISSUE_REF_CHARS` with `…`, else `#id` — one helper per side of the wire, so the same issue never wears two names and no notice renders an empty head or dangling separator.

**Board and live state are TWO AXES, never merged**: the board is the ISSUE's lifecycle, while the WINDOW's turn is hook-derived. An agent can be running on something else while its issue sits in review. Every board status change posts a `[tmm] board #N a → b — title` room line; a move TO REVIEW is a HANDOFF delivered into the REPORTER's pane via `deliver_chat_line`. A change somebody else makes to an ASSIGNED issue reaches the ASSIGNEE the same way, and a NOTE on an issue reaches BOTH declared parties — the assignee and the reporter — minus its author and minus the human (`board_note_notice`, #255). The recipients come from the issue, never from the note's text, so a third party's note (a reviewer's SHIP on an issue the lead opened) reaches the lead as well as the implementer. Incident (2026-09-27, `temp/stall-analysis.md`): this line said "the reporter when the assignee notes" while the code woke only the assignee and a unit test pinned that; five of six stalls were a SHIP or a "ready to merge" note that never reached the merger (worst 3h27m on #248, 46 min on #241), and agents doubled every note with an @message (60 pairs in 14h) because a note was not trusted to arrive. A note reaches both sides, so nobody needs to @ them as well. **The pane notice has THREE shapes and the feed reads all three** (board #172): `[board #N] title: what` (a change), `[board #N review] title — last note. …` (the handoff), `[board #N reply] title — note. …` (a note); `promptParts` in hub.ts turns each into the issue chip plus, for review/reply, ONE badge coloured by `boardStatusColor` (reply is not a status and takes its default reading ink). Owner, 2026-09-11 ("有消息没有渲染"): the reply shape was typed by the server but unknown to the reader, so the input row showed the raw marker — a new server shape MUST be added to `promptParts` and its unit vectors in the same commit. The note body is an EXCERPT by design (`NOTICE_EXCERPT`, 400 chars, `…` when cut): the pane gets the context, the issue holds the whole note (`tmm board show N`). The ideal loop: 人填 issue → lead 派（指派即投递）→ 子 agent take → 完成 move review（提报人被通知）→ 通过 move done / 打回 note+doing.

**Motion** (per [motion.md](motion.md)): on a phone the `{#if sel}` detail ↔ columns swap is a navigation, so it wears the drill grammar AgentsPage speaks — the detail enters from the right, the columns re-enter from the left, 120ms linear, derived from one `drilled` flag (issue → issue does not replay), inert on desktop and under reduced motion. Same-column cards move with `animate:flip` on `moveMs()` (the each is keyed by id); the status slider has ONE highlight that travels (principle 14, wave 7): a `.slide-pill` behind the stops carries the wash + inset ring and glides to the chosen stop (`use:slideIndicator={{ key: draft.status, active: '.on' }}` on the `position: relative` track; stops are `z-index: 1`), while `.seg-b.on` keeps only the accent ink and the divider beside the chosen stop goes transparent so the ring reads whole; the draft's undo/✓ pop in (`.appear-pop`); a note's `.m-acts` row and the `.err` line fade in; notes are keyed and only a note that ARRIVES after the issue was opened fades in (`notesBase`, a count — notes append and are never removed in the UI). The sidebar drawer keeps the shared `.side-sheet` motion; the Select popover grows from its trigger (`.pop-layer`). **Unfold** (principle 15): a project's board unfolds on its FIRST fill — `load()` calls `unfold()` only while `ready` is still false (the switch effect resets it), `justLoaded` puts `.reveal` on every `.col-scroll` for one `revealMs()` window, and the 8s poll stays a cut (a card that moves has `animate:flip`, a card that arrives on a poll mounts plain). **Hover** (principle 16; board #284, owner 2026-09-30: "悬浮窗展示的信息有很多是和上边我已经看到的重复的，不要做重复内容展示"): a column card opens the one hover card through `use:hoverInfo` with ONLY what the card does not say. The card already shows the title, the body preview, `#N`, the reporter, `@assignee`, the note count and the age, and its column is the status, so the hover repeats none of them. What the card lacks is WHEN: the update is a relative age and the creation is absent, so the hover gives `created` and, when it differs, `updated` as absolute local times (`hub.ts` `localWhen`, the same form as the agent card's wake row). A clamped body gets no hover: the card is the door to the detail (the preview's own rule). An issue with no time has nothing more to say and opens no card. The latest note would be new information too, but the list payload carries only a note count; it is not added for this. No native `title` beside it.
